**Objective**: Extract HierarchicalKey class from System.Distributed.DurableTasks and make it publicly available in Orleans.Core.Abstractions as a foundation for hierarchical routing and correlation in Orleans messaging.

**Implementation Details**:

1. **Created new public HierarchicalKey class** (`src/Orleans.Core.Abstractions/HierarchicalKey.cs`)
   - Changed namespace from `System.Distributed.DurableTasks` to `Orleans`
   - Changed visibility from `internal sealed class` to `public sealed class`
   - Added serialization attributes: `[GenerateSerializer, Immutable]`
   - Added `[Id(0)]` and `[Id(1)]` attributes to private fields for Orleans serialization
   - Preserved all original functionality including:
     - Hierarchical key creation and parsing

### Completed: Create deprecated CorrelationKey wrapper for backward compatibility (Feature #4)

**Objective**: Convert CorrelationKey from a standalone implementation to a wrapper around HierarchicalKey, providing backward compatibility for existing code while enabling migration to the new unified type.

**Implementation Details**:

1. **Refactored CorrelationKey.cs** (\src/Orleans.Journaling/Messaging/CorrelationKey.cs\)
   - Converted from standalone implementation to wrapper class
   - Added private readonly field \_inner\ of type \HierarchicalKey\
   - Implemented implicit conversion operators:
     * \CorrelationKey? → HierarchicalKey?\
     * \HierarchicalKey? → CorrelationKey?\
   - Delegated all methods to wrapped HierarchicalKey instance:
     * Create, Parse, TryParse methods
     * GetParent, IsParentOf, IsChildOf, IsAncestorOf
     * CreateChildKey, CreateEscapedChildKey, CreateEscaped
     * ToString, Equals, GetHashCode, TryFormat
     * SegmentEnumerator now wraps HierarchicalKey.SegmentEnumerator
   - Kept \[GenerateSerializer, Immutable]\ attributes for serialization compatibility
   - Added deprecation notice in XML documentation (not using [Obsolete] attribute to avoid code generator issues)

2. **Key Design Decisions**:
   - **No [Obsolete] attribute**: Using [Obsolete] caused CS0618 errors in generated serialization code
   - **Implicit conversions**: Enable seamless interop between CorrelationKey and HierarchicalKey
   - **Full API preservation**: All existing CorrelationKey methods remain available
   - **Serialization compatibility**: Maintains Orleans serialization support via [GenerateSerializer]

Users can gradually migrate from CorrelationKey to HierarchicalKey:
\\\csharp

transfer-123\);

// Implicit conversion (seamless):

HierarchicalKey newKey = oldKey; // Implicit conversion
\\\
